# 카드 템플릿 참고 자료

앞으로 만들 카드 디자인의 참고로 모은 것들이다. 화면 캡처는 남의 게시물이라
저장소에 넣지 않고, 읽어낸 것만 글로 적는다.

**두 종류가 섞여 있다.** A·B 는 베낄 수 있는 **디자인 견본**이고, C·D 는
만드는 법을 설명한 **규칙**이다. 규칙 쪽은 옮겨 그릴 것이 없는 대신 지금
구현과 숫자를 맞대 볼 수 있다.

읽는 법: 레이아웃과 색 구성은 참고하되 그대로 베끼지 않는다. 공개적으로
올리는 콘텐츠이므로 남의 브랜드 디자인을 통째로 옮기면 곤란해진다.

---

## A. 어두운 단색 + 단일 포인트 컬러 (11장)

출처: 인스타그램 `31brand` / "CAROUSEL PLAYBOOK" 연작

**우리 축으로는 `background: "color"`, `font: "sans"`.** 사진이 한 장도 없어
지금 구조로 바로 만들 수 있는 종류다.

### 읽어낸 규격

| 요소 | 값 |
| --- | --- |
| 배경 | 거의 검정(대략 `#0A0A0C`), 아주 옅은 격자 텍스처 |
| 분위기 | 우하단 모서리에 자주~분홍 글로우가 은은하게 번짐 |
| 포인트 컬러 | 핫핑크 하나만 (대략 `#FF2D78`) |
| 정렬 | 전부 좌측 |
| 공통 마커 | 좌상단에 짧고 굵은 핑크 가로 바. 모든 장에 있음 |
| 워터마크 | 좌하단에 아주 흐린 회색 소문자 영문 |

### 글자 위계가 네 단계

이게 이 연작의 핵심이다. 한 장 안에서 네 종류를 섞어 리듬을 만든다.

1. **큰 흰 헤드라인** — 굵게
2. **중간 회색 설명문** — 보통 굵기. 톤을 낮춰 배경처럼 깔림
3. **흰 강조 문장** — 굵게. "틀렸다.", "이미 진 거다." 같은 짧은 단정
4. **핑크 강조** — 단어나 짧은 구절. 한 장에 한두 번만

### 장별 변형

- **표지**: 핑크 바 → 큰 헤드라인 3~4줄(그중 **한 줄만 핑크**) → 작은 회색 서명
- **상세**: 핑크 바 → 핑크 라벨(`Rule #1`) + 흰 헤드라인 → 위계 섞인 본문
- **목록**: 작은 핑크 정사각형 불릿
- **마무리**: 큰 문구 + 핑크 아래 화살표

## B. 무언가를 흉내낸 프레임 (5장)

출처: 인스타그램 `marketer_c_` / "인스타 카드뉴스 스타일 5종"

| 예시 | 흉내내는 것 | 쓰임새 |
| --- | --- | --- |
| 1 | 노란 종이에 손글씨 + 낙서 + 테이프 + 형광펜 | 감성·공감·자기계발 |
| 2 | 카카오톡 대화창 | 스토리텔링·후기·썰 |
| 3 | 노션 문서 (체크박스 목록) | 정보성·생산성 |
| 4 | 아이패드 필기 화면 | 공부·요약·꿀팁 |
| 5 | 웹사이트 랜딩 페이지 | 브랜딩 |

**이 다섯은 우리 축에 들어가지 않는다.** 배경을 무엇으로 채우는가의 문제가
아니라, 카드 전체가 다른 물건인 척하는 것이다. 굳이 넣는다면
`BackgroundKind`에 `mockup`을 더해야 한다.

## C. 제작 가이드 — 글자 크기 수치 (4장)

출처: 인스타그램 `indoorsy_squirrel` / "방구석 다람쥐"

**이건 베낄 디자인이 아니라 규칙이다.** 흰 배경에 회색 `PHOTO` 자리를 표시한
설계도 형태로, 1080×1350 기준의 구체적인 글자 크기를 제시한다.

### 표지

| 요소 | 크기 | 굵기 | 위치 |
| --- | --- | --- | --- |
| 부제목 | 45p | 보통 | 타이틀 위 |
| 타이틀 | 60p | 두껍게 | 부제목 아래 |
| 사진 | — | — | 우측 중앙 |
| 출처 | 25p | 두껍게 | 좌측 하단 |
| 콘텐츠 설명 | 25p | 얇게 | 출처 아래 |

### 본문

| 요소 | 크기 | 굵기 | 위치 |
| --- | --- | --- | --- |
| 출처 | 15p | 얇게 | 우측 상단 |
| 사진 | — | — | 위쪽, **크게** |
| 본문 타이틀 | 45p | 두껍게 | 사진 아래 |
| 본문 내용 | 28p | 얇게 | **3줄 이내** |

### 본문에 적힌 조언

- 타이틀 페이지는 **좌측 정렬**로 가독성을 높인다
- 폰트는 **프리텐다드, 에스코어드림** 같은 깔끔한 느낌을 추천
- 본문은 **텍스트보다 사진을 크게** 넣어 한눈에 알아보게
- 멈춘 이미지보다 움직이는 이미지가 집중도가 높으니 PNG보다 **GIF**가 낫다

## D. 제작 가이드 — 잘못된 예시 대 올바른 예시 (5장)

출처: 인스타그램 `platformtree_`

역시 규칙이다. 베이지 배경에 빨강·초록으로 비교해 보여준다.

| 주제 | 잘못 | 올바름 |
| --- | --- | --- |
| 표지 텍스트 | 설명이 문단으로 빽빽 | 짧은 헤드라인 + 시선이 1→2→3으로 흐르게 |
| 규격 | 1080 × 1080 (정사각) | 1080 × 1350, 1080 × 1440 (세로) |
| 디자인 | 요소가 가득한 복잡한 판 | 단순하게. 강조는 형광펜 같은 배경색 한 군데 |
| 구성 | 긴 헤드라인 → 지루한 도입 → 무작위 → 복잡한 마무리 | 후킹 → 참여 유도 → 단계별 전달 → 마무리 |

## C·D를 지금 구현과 대조하면

가이드가 제시한 값과 우리가 쓰고 있는 값이 꽤 다르다. 옮겨 적기 전에 왜
다른지부터 봐야 한다.

| 항목 | 가이드 | 지금(`GradientCenter`) |
| --- | --- | --- |
| 표지 헤드라인 | 60p | **92px** |
| 표지 부제 | 45p | 36px |
| 상세 헤드라인 | 45p | **62px** |
| 본문 | 28p | 38px |
| 본문 줄 수 | 3줄 이내 | 최대 4줄 |
| 출처 | 15~25p | 24px |

**우리가 전반적으로 크다.** 다만 가이드의 판에는 사진이 자리를 크게 차지하고
우리는 글자만 있다. 같은 칸을 글자가 다 쓰니 커지는 것이 자연스럽다.
**사진을 넣게 되면 이 수치 쪽으로 내려와야 한다.**

### 그대로 받아들이기 어려운 것

- **1080 × 1440** — 가이드가 세로 규격으로 함께 제시하지만, 인스타그램 피드가
  이 비율을 자르지 않고 보여주는지 확인하지 않았다. 지금은 4:5(1350)로 둔다.
- **마지막 장에서 "선물 약속 후 챗봇으로 전달"** — 리드를 모으는 마케팅 패턴이다.
  공공기관 뉴스에는 맞지 않는다.
- **GIF** — 움직이는 카드를 만들려면 애니메이션 소스와 인코딩이 필요하다.
  지금 구조(DOM을 PNG로 캡처)와는 별개의 작업이다.

### 폰트

가이드가 추천한 **프리텐다드**는 npm 에 `pretendard`(OFL-1.1)로 있어 넣으려면
넣을 수 있다. 다만 지금 쓰는 원티드산스도 같은 계열(모던 고딕)이라 급하지 않다.
굳이 바꿔야 할 이유가 생기면 그때 넣는다.

## 넣기 전에 풀어야 할 것 두 가지

받은 자료를 그대로 구현하려다 막히는 지점이 두 군데 있다. 미리 적어 둔다.

### 1. 문장 안의 한 단어만 색을 바꿀 수 없다

A 연작은 `그 "하지만"이 계속 넘기게 만든다` 처럼 **한 줄 안에서 일부만**
핑크로 칠한다. 지금 `CardSlide.heading`과 `.body`는 그냥 `string[]`이라
줄 단위로만 다룰 수 있고 줄 안의 일부를 가리킬 수단이 없다.

해결하려면 데이터 형식을 바꿔야 한다. 예를 들어 한 줄을 조각 배열로 받는 식:

```
body: [
  [{ text: "그 " }, { text: "\"하지만\"", accent: true }, { text: "이" }],
  [{ text: "계속 넘기게 만든다." }]
]
```

프롬프트도 같이 고쳐야 하고, 모델이 강조할 곳을 잘 고르는지도 확인해야 한다.
**줄 단위 강조(한 줄 통째로 핑크)만이라면 훨씬 싸게 된다.** 어디까지 필요한지
먼저 정하는 게 좋다.

### 2. B는 디자인이 아니라 콘텐츠 구조가 다르다

카카오톡 스타일은 말풍선이 오가는 **대화**고, 노션 스타일은 **체크리스트**,
웹사이트 스타일은 **섹션 묶음**이다. 지금의 `heading[] + body[]` 로는
표현할 수 없다. 껍데기만 흉내내고 안에 평범한 문단을 넣으면 어색해진다.

그래서 B를 하려면 템플릿마다 다른 데이터 모양이 필요하고, 그건 프롬프트도
템플릿 수만큼 갈린다는 뜻이다. A보다 훨씬 큰 작업이다.

### 그리고 폰트

- A 연작: 지금 있는 원티드산스로 충분하다.
- B의 1번과 4번: **손글씨 글꼴이 필요하다.** 자유 라이선스 한글 손글씨체를
  새로 넣어야 한다.
- B의 3번(노션): 본문용 고딕이면 되지만 노션 특유의 회색조와 아이콘이 필요하다.

## 순서 제안

1. **A 연작을 색 배경 템플릿으로 추가** — 지금 구조로 바로 된다. 가장 싸고
   효과가 크다.
2. **강조 범위를 정한다** — 줄 단위면 저렴, 단어 단위면 데이터 형식 변경.
3. **본문 줄 수를 3줄로 줄일지 정한다** — C 가 권하는 값이다. 프롬프트의
   `[줄바꿈 규칙]` 과 `cardnews.ts` 의 `toLines` 상한만 고치면 되는 작은 일이다.
4. **B는 나중에** — 하나씩, 데이터 모양부터 정하고 들어간다.
5. **사진을 넣게 되면 글자 크기를 C 쪽으로 내린다** — 사진이 자리를 차지하면
   지금 크기로는 넘친다.
