# 카드 템플릿 참고 자료

앞으로 만들 카드 디자인의 참고로 모은 것들이다. 화면 캡처는 남의 게시물이라
저장소에 넣지 않고, 읽어낸 것만 글로 적는다.

**두 종류가 섞여 있다.** A·B 는 베낄 수 있는 **디자인 견본**이고, C·D 는
만드는 법을 설명한 **규칙**이다. 규칙 쪽은 옮겨 그릴 것이 없는 대신 지금
구현과 숫자를 맞대 볼 수 있다.

읽는 법: 레이아웃과 색 구성은 참고하되 그대로 베끼지 않는다. 공개적으로
올리는 콘텐츠이므로 남의 브랜드 디자인을 통째로 옮기면 곤란해진다.

## A. 어두운 단색 + 단일 포인트 컬러 (11장)

출처: 인스타그램 `31brand` / "CAROUSEL PLAYBOOK" 연작

**우리 축으로는 `background: "color"`, `font: "sans"`.** 사진이 한 장도 없어
지금 구조로 바로 만들 수 있는 종류다.

### 읽어낸 규격

| 요소 | 값 |
| --- | --- |
| 배경 | 거의 검정(대략 `#0A0A0C`), 아주 옅은 격자 텍스처 |
| 분위기 | 우하단 모서리에 자주~분홍 글로우가 은은하게 번짐 |
| 포인트 컬러 | 핫핑크 하나만 (대략 `#FF2D78`) |
| 정렬 | 전부 좌측 |
| 공통 마커 | 좌상단에 짧고 굵은 핑크 가로 바. 모든 장에 있음 |
| 워터마크 | 좌하단에 아주 흐린 회색 소문자 영문 |

### 글자 위계가 네 단계

이게 이 연작의 핵심이다. 한 장 안에서 네 종류를 섞어 리듬을 만든다.

1. **큰 흰 헤드라인** — 굵게
2. **중간 회색 설명문** — 보통 굵기. 톤을 낮춰 배경처럼 깔림
3. **흰 강조 문장** — 굵게. "틀렸다.", "이미 진 거다." 같은 짧은 단정
4. **핑크 강조** — 단어나 짧은 구절. 한 장에 한두 번만

### 장별 변형

- **표지**: 핑크 바 → 큰 헤드라인 3~4줄(그중 **한 줄만 핑크**) → 작은 회색 서명
- **상세**: 핑크 바 → 핑크 라벨(`Rule #1`) + 흰 헤드라인 → 위계 섞인 본문
- **목록**: 작은 핑크 정사각형 불릿
- **마무리**: 큰 문구 + 핑크 아래 화살표

## E. 검정 + 빨강/노랑 2색 · 10장 연작 (10장)

출처: 인스타그램 `biju_twinkle` / 박비주 작가 "실전 방어 매뉴얼 7"

**지금까지 받은 것 중 정보 밀도가 가장 높다.** 10장이 통째로 한 세트라
표지·정보장·마무리가 어떻게 역할을 나누는지 다 보인다.

> **내용과 말투는 가져오지 않는다.** 이 연작은 거친 구어체 자기계발 콘텐츠고
> 우리는 공공기관 MICE 뉴스다. 가져오는 것은 **구조와 강조 기법**뿐이다.

### 읽어낸 규격

| 요소 | 값 |
| --- | --- |
| 배경 | 거의 검정. 표지에만 좌측 세로 빨강 띠 |
| 포인트 컬러 | **두 개**. 빨강(대략 `#E8372B`)과 노랑(대략 `#F5C518`) |
| 정렬 | 전부 좌측 |
| 고정 틀 | 좌상단 작성자 서명, 우상단 쪽수, 좌하단 `@핸들` |
| 글꼴 | 굵은 고딕 한 종. 굵기 차이로만 위계를 만든다 |

### 1. 포인트 컬러가 두 개고, 역할이 다르다

이게 제일 큰 차이다. 우리는 네온 한 색뿐이다.

| 색 | 맡은 일 | 예 |
| --- | --- | --- |
| **빨강** | 경고·부정·단절 | 라벨(`TRUTH NO.1`), 취소선, 틀린 예 박스, "죄", "칼", "거절" |
| **노랑** | 해법·핵심어 | 맞는 예 박스, "권리", "비대칭", "스킬", 수치 |

같은 장에서 둘을 같이 쓰되 **섞어 쓰지 않는다.** 빨강이 문제를 가리키면
노랑이 답을 가리킨다.

### 2. 강조 기법이 네 가지다

**우리는 "색 바꾸기" 하나뿐이다.** 하나를 반복하면 폭이 없어서 결국 묻힌다.
여기서 "강조가 눈에 안 들어온다"는 느낌의 원인이 설명된다.

| 기법 | 쓰임 |
| --- | --- |
| **색만 바꾸기** | 가장 가벼움. 핵심 낱말 |
| **블록 하이라이트** | 형광펜처럼 배경을 칠함. 가장 셈. 표지에 한 번 |
| **취소선** | 회색 글자 + 빨간 줄. "이건 아니다"를 한 번에 보여줌 |
| **밑줄** | 노란 밑줄. 결론 문장에 |

표지에서는 같은 낱말("샹년")을 **블록 하이라이트와 색 바꾸기로 두 번** 썼다.
같은 말인데 다르게 칠해서 리듬을 만든다.

### 3. 헤드라인이 압도적으로 크다

표지 헤드라인이 **다섯 줄로 카드 높이의 절반 이상**을 차지한다. 우리 92px
이 작아 보일 정도다. 글자로만 하는 카드에서는 이 정도까지 간다.

### 4. 정보형의 본문은 문장이 아니라 **행**이다

**이게 "작은 내용의 나열" 문제의 진짜 답이다.**

이 연작은 정보장에서 **흐르는 문장을 네 줄 쓰지 않는다.** 대신 구조가 있는
행을 쓴다.

```
01   호의 베풀면      →   당연하게 여김        (번호 / 조건 / 화살표 / 결과)
FIRST   "혹시 가능하면..."                      (라벨 / 인용)
01   단답  으로만 말한다                        (번호 / 핵심어 / 나머지)
```

행 **안에서** 색과 굵기가 갈린다. 번호는 빨강, 왼쪽은 흰색, 오른쪽은 노랑
굵게. 그래서 네 줄이어도 나열로 안 읽힌다. **우리 `body` 는 같은 크기·같은
색 문장이 네 줄 쌓이니까 나열로 읽힌다.** 줄 수가 문제가 아니라 줄의 구조가
문제였다.

### 5. 정보장은 거의 다 "결론 상자"로 끝난다

데이터를 늘어놓고 끝내지 않는다. 마지막에 테두리 있는 상자를 두고 거기에
두 줄짜리 결론을 넣는다. **데이터와 결론이 눈으로 분리된다.**

상자가 장이 갈수록 세진다. 빨강 테두리 → 흰색 채움 → 빨강 채움. 뒤로 갈수록
목소리가 커진다.

### 6. 라벨이 두 조각이다

`TYPE 01`(빨강 알약) + `샹년의 특징`(회색 작은 글씨). 우리 배지는 한 덩어리다.
분류와 설명을 나눠 두니 배지가 작아도 정보가 더 들어간다.

### 7. 큰 숫자를 시각 앵커로 쓴다

`01` `02` `03` 을 거대한 숫자로 올리고 빨간 밑줄을 긋는다. 글자만 있는
화면에서 숫자가 도형 역할을 한다.

### 두 모드가 여기서 확인된다

| | 해당 장 | 헤드라인 | 본문 |
| --- | --- | --- | --- |
| **헤드라인형** | 표지, `TRUTH NO.1`, 마무리 | 3~5줄, 아주 큼 | 없거나 **작은 회색 3줄** |
| **정보형** | `TYPE`, `TACTIC` 장 | 2줄, 중간 | **구조 있는 행 3~4개** + 결론 상자 |

**본문이 4줄을 넘는 장이 하나도 없다.** 다만 정보형의 4줄은 문장이 아니라
행이다.

## B. 무언가를 흉내낸 프레임 (5장)

출처: 인스타그램 `marketer_c_` / "인스타 카드뉴스 스타일 5종"

| 예시 | 흉내내는 것 | 쓰임새 |

### 본문

| 요소 | 크기 | 굵기 | 위치 |
| --- | --- | --- | --- |

## C·D를 지금 구현과 대조하면

가이드가 제시한 값과 우리가 쓰고 있는 값이 꽤 다르다. 옮겨 적기 전에 왜
다른지부터 봐야 한다.

| 항목 | 가이드 | 지금(`GradientCenter`) |
| --- | --- | --- |
| 표지 헤드라인 | 60p | **92px** |
| 표지 부제 | 45p | 36px |
| 상세 헤드라인 | 45p | **62px** |
| 본문 | 28p | 38px |
| 본문 줄 수 | 3줄 이내 | 최대 4줄 |
| 출처 | 15~25p | 24px |

**우리가 전반적으로 크다.** 다만 가이드의 판에는 사진이 자리를 크게 차지하고
우리는 글자만 있다. 같은 칸을 글자가 다 쓰니 커지는 것이 자연스럽다.
**사진을 넣게 되면 이 수치 쪽으로 내려와야 한다.**

### 그대로 받아들이기 어려운 것

- **1080 × 1440** — 가이드가 세로 규격으로 함께 제시하지만, 인스타그램 피드가
  이 비율을 자르지 않고 보여주는지 확인하지 않았다. 지금은 4:5(1350)로 둔다.
- **마지막 장에서 "선물 약속 후 챗봇으로 전달"** — 리드를 모으는 마케팅 패턴이다.
  공공기관 뉴스에는 맞지 않는다.
- **GIF** — 움직이는 카드를 만들려면 애니메이션 소스와 인코딩이 필요하다.
  지금 구조(DOM을 PNG로 캡처)와는 별개의 작업이다.

### 폰트

가이드가 추천한 **프리텐다드**는 npm 에 `pretendard`(OFL-1.1)로 있어 넣으려면
넣을 수 있다. 다만 지금 쓰는 원티드산스도 같은 계열(모던 고딕)이라 급하지 않다.
굳이 바꿔야 할 이유가 생기면 그때 넣는다.

## 다음에 다듬을 방향 — 더하지 말고 빼기

2026-09-30 에 정해진 방향이다. 글자를 키운 뒤에도 뭔가 아쉽다는 이야기가
나왔고, **원인 진단이 두 갈래로 갈렸다.**

- (틀린 쪽) 위계가 두 단계뿐이라 밋밋하다 → 네 번째 단계를 **더하자**
- (맞는 쪽) **작은 내용의 나열이 너무 많다** → 그걸 **빼자**

강조가 눈에 안 들어오는 것은 강조가 약해서가 아니다. **주변에 비슷한 무게의
작은 글이 깔려 있어서**다. 4줄짜리 본문이 헤드라인의 힘을 깎고, 그 안에서
강조 한두 개는 같이 묻힌다.

카드뉴스는 한 장에 하나를 남기는 물건이다. 정보를 다 담으려고 줄을 늘리면
**아무것도 안 남는다.** 넣을 것을 고르는 게 아니라 버릴 것을 고르는 쪽이다.

이미 열려 있던 항목(**본문 4줄 → 3줄**, 참고 자료 C 의 "3줄 이내")과 같은
이야기다. 그때는 숫자 문제로만 봤는데, 이유가 분명해졌다.

### 한 가지 답이 아니라 두 모드다

이야기를 이어 가다 더 나은 틀이 나왔다. **"본문을 3줄로 줄인다"가 아니라
상황에 따라 두 모드를 쓴다**는 것이다.

| 모드 | 언제 | 화면 |
| --- | --- | --- |
| **정보형** | 수치와 사실이 많아 줄이 필요할 때 | 헤드라인 + 여러 줄 본문 |
| **헤드라인형** | 한 마디로 치고 빠질 때 | 큰 헤드라인만. 강조로 플레이 |

**이게 생각보다 싸게 된다.** 지금 데이터가 이미 `heading` 과 `body` 로
나뉘어 있어서, **헤드라인형은 `body` 가 빈 장**이다. 새 데이터 형식이
필요 없다. 바뀌는 곳은 두 군데뿐이다.

- **렌더링** — 지금은 장 종류(`kind`)로 글자 크기를 정한다. 이걸 **본문이
  있는지 없는지**로 정하면 된다. 본문 없는 장은 헤드라인을 훨씬 키운다.
- **프롬프트** — 어떤 장을 어느 모드로 쓸지 모델에게 알려준다.

**아직 손대지 않는다.** 말로만 주고받으면 서로 다른 그림을 그리게 되므로,
두 모드 각각의 레퍼런스를 받아 확인한 뒤에 옮긴다.

## 넣기 전에 풀어야 할 것 두 가지

받은 자료를 그대로 구현하려다 막히는 지점이 두 군데 있다. 미리 적어 둔다.

### 1. 문장 안의 한 단어만 색을 바꿀 수 없다

A 연작은 `그 "하지만"이 계속 넘기게 만든다` 처럼 **한 줄 안에서 일부만**
핑크로 칠한다. 지금 `CardSlide.heading`과 `.body`는 그냥 `string[]`이라
줄 단위로만 다룰 수 있고 줄 안의 일부를 가리킬 수단이 없다.

해결하려면 데이터 형식을 바꿔야 한다. 예를 들어 한 줄을 조각 배열로 받는 식:

```
body: [
  [{ text: "그 " }, { text: "\"하지만\"", accent: true }, { text: "이" }],
  [{ text: "계속 넘기게 만든다." }]
]
```

프롬프트도 같이 고쳐야 하고, 모델이 강조할 곳을 잘 고르는지도 확인해야 한다.
**줄 단위 강조(한 줄 통째로 핑크)만이라면 훨씬 싸게 된다.** 어디까지 필요한지
먼저 정하는 게 좋다.

### 2. B는 디자인이 아니라 콘텐츠 구조가 다르다

카카오톡 스타일은 말풍선이 오가는 **대화**고, 노션 스타일은 **체크리스트**,
웹사이트 스타일은 **섹션 묶음**이다. 지금의 `heading[] + body[]` 로는
표현할 수 없다. 껍데기만 흉내내고 안에 평범한 문단을 넣으면 어색해진다.

그래서 B를 하려면 템플릿마다 다른 데이터 모양이 필요하고, 그건 프롬프트도
템플릿 수만큼 갈린다는 뜻이다. A보다 훨씬 큰 작업이다.

### 그리고 폰트

- A 연작: 지금 있는 원티드산스로 충분하다.
- B의 1번과 4번: **손글씨 글꼴이 필요하다.** 자유 라이선스 한글 손글씨체를
  새로 넣어야 한다.
- B의 3번(노션): 본문용 고딕이면 되지만 노션 특유의 회색조와 아이콘이 필요하다.

## 순서 제안

1. **A 연작을 색 배경 템플릿으로 추가** — 지금 구조로 바로 된다. 가장 싸고
   효과가 크다.
2. **강조 범위를 정한다** — 줄 단위면 저렴, 단어 단위면 데이터 형식 변경.
3. **본문 줄 수를 3줄로 줄일지 정한다** — C 가 권하는 값이다. 프롬프트의
   `[줄바꿈 규칙]` 과 `cardnews.ts` 의 `toLines` 상한만 고치면 되는 작은 일이다.
4. **B는 나중에** — 하나씩, 데이터 모양부터 정하고 들어간다.
5. **사진을 넣게 되면 글자 크기를 C 쪽으로 내린다** — 사진이 자리를 차지하면
   지금 크기로는 넘친다.
